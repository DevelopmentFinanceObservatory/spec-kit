# python/dfo-spec-kit-components/src/dfo_spec_kit_components/catalogue

This is the presentation contract bundle: the envelope and component JSON Schemas that resolved payloads validate against, the write-side intent grammar that client requests validate against before they reach the assembler, worked and minimal intents, resolved-payload fixtures, constraint fixtures, and the manifest that digests all of it.

## Package data

The bundle ships as package data inside `dfo_spec_kit_components` (`src/dfo_spec_kit_components/catalogue/`, installed at `dfo_spec_kit_components/catalogue/`), the same layout `dfo_frame_grammar` uses for its golden vector suite. Installing the package delivers the schemas, the grammar, and the fixtures. `dfo_spec_kit_components.bundle_dir()` locates the installed bundle from a repo checkout and from a wheel.

## Format

| Path                                             | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `manifest.json`                                  | `catalog_version`, `schema_version`, a `sha256:`-prefixed digest of every other JSON artifact in this bundle, `encoding_classes` and `retry_modes` per component/code, and the `formatter_profile` resolved payloads are formatted against.                                                                                                                                                                                                                                                                                                                               |
| `schemas/intent.v0.json`                         | The write-side intent grammar, a draft 2020-12 `oneOf` over the six writable component shapes (`line_chart`, `bar_chart`, `table`, `stat_card`, `note_narration`, `source_card`). It validates a create or revise intent before the assembler sees it. The assembler's named rules (the one-arrayed-dimension rule, data-judged bindings) apply on top, because JSON Schema cannot express rules over open dimension keys. This release ships all six writable types. An intent naming a type a narrower release does not serve refuses with the `release_mismatch` code. |
| `schemas/envelope.schema.json`                   | The one shape every resolved component payload has: `schema_version`, `catalog_version`, `component_id`, `revision`, `provenance`, and a `component` closed to the members this release ships.                                                                                                                                                                                                                                                                                                                                                                            |
| `schemas/component/*.schema.json`                | One resolved-payload schema per catalogue member (`line_chart`, `bar_chart`, `table`, `stat_card`, `note_narration`, `source_card`).                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `intents/*.minimal.json`                         | The smallest intent that validates against `schemas/intent.v0.json` for each member: one dimension, one value, nothing else where the member's shape has a `select`; `note_narration`'s is `{type, text}` and `source_card`'s is `{type, frame_ref}`, the member's whole writable shape.                                                                                                                                                                                                                                                                                  |
| `fixtures/<member>/intent.json` + `payload.json` | A worked example per member: an intent that validates against the grammar, paired with the resolved envelope-and-component payload that intent produces. `fixtures/bar_chart/payload_span.json` adds an entity-mode bar whose bars cover the span `2018/2022`.                                                                                                                                                                                                                                                                                                            |
| `fixtures/constraints/<constraint_id>/*.json`    | Positive and negative cases for the assembler's five named constraints (`comparable_units_required`, `log_scale_requires_positive_values`, `range_contains_visible_data`, `stat_change_basis_observed`, `bar_zero_in_domain`). Each constraint reasons across several fields or against frame data, beyond what a JSON Schema can judge.                                                                                                                                                                                                                                  |

## The selector shape

An intent's `select` is a flat object mapping dimension name to value. A value is a single string or, for at most one dimension, an array of strings. A one-value binding is a plain string, `{"stat_var": "health_oda"}`. The shape comes from the grammar itself (`schemas/intent.v0.json`). The assembler judges completeness of the selection, the one-arrayed-dimension rule, and whether a named value exists in the referenced frame.

## Adding a schema or fixture

1. A schema change starts in the normative presentation contract this bundle implements.
1. Add or edit the JSON file under `schemas/`, `intents/`, or `fixtures/`.
1. Regenerate `manifest.json`'s digest for every artifact you touched, and add an entry for a new file. Each digest is `"sha256:" + hex(sha256(file_bytes))`, computed over the file exactly as it sits on disk.
1. Confirm every intent under `intents/` and `fixtures/*/intent.json` validates against `schemas/intent.v0.json`, every payload under `fixtures/*/payload.json` validates against `schemas/envelope.schema.json`, and `uv run pytest` passes from `python/dfo-spec-kit-components/`.
