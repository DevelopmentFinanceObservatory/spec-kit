# registries

`codes.json` is the seeded instance of the platform's code registry, every permanent warning and refusal code across the contracts this kit distributes, sorted by code. The format (field semantics, the addition rule, classification, and the endpoint/door/channel vocabulary) is documented in `schemas/registry/README.md`, which also owns the JSON Schema that validates this file. Run `uv run tools/validate_registry.py` after editing it.

This file is the canonical copy. `python/spec-kit/src/dfo_spec_kit/registry/codes.json` is a byte-identical package mirror, kept in sync by the same validator, so a Python consumer can load the registry from an installed wheel via `dfo_spec_kit.registry` without a filesystem path back to this directory. Edit this file, not the mirror; `uv run tools/validate_registry.py` fails loudly if they diverge.

`units.json` declares how unit refs read as typed units, for `dfo_spec_kit.units`. `currency_prefixes` lists the prefixes (`""` and `Currency`) that, followed by a currency code, make a ref money in that currency with prices unstated. After `Currency` a code is any three upper-case ASCII letters. After the empty prefix the code must be one of `currency_codes`, the ISO 4217 active codes without `XTS` (testing) and `XXX` (no currency), plus the withdrawn `ANG`, `BGN` and `ZWL`, which Data Commons still types as `Currency` for older series, so a bare `TEU` or `PPM` reads as other. `units` lists every other typed ref, sorted by `ref`. Money rows carry `currency`, `prices` (`current`, `constant`, or `null` when the ref leaves them unstated) and `evidence`; a row with stated prices also carries `base_year` (`null` when unstated, always `null` for current prices) and `chained` (`true` for a chain-linked series, which only constant prices can be). Percent and count rows carry `ref`, `kind` and `evidence` only. Rate rows state a value per a count of something: `count_base` is that count (`1000` for "per 1,000 people"), and `counted` is what it counts as a plural noun phrase (`people`, `live births`), `null` when the ref states none. The graph holds neither as a field, so each rate row declares them from the ref and its label. `evidence` says where the reading comes from. A ref that scales its values (`SDG_CU_USD_M`, `SDG_NUM_TH`, `PeopleInThousands`) has no row and reads as other, as does any ref that matches no prefix and no row. No row may also match a prefix rule. `schemas/registry/unit-registry.schema.json` validates the file, and `uv run tools/validate_unit_registry.py` also checks the sort order, uniqueness, the prefix rule and the package mirror `python/spec-kit/src/dfo_spec_kit/units/units.json`; edit this file and copy it there.
